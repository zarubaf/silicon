# One line for each gap: `<part> | <row> | <issue>`.
#   part   one of `fix`, `lean`, `rust`, `pin`: the part of the text that is missing.
#   row    the code and the case of a row of a message table of section 6.2, as the
#          rule prints it, for example `S021 Uncovered value`.
#   issue  the number of the issue that closes the gap, with no `#`.
# A line that starts with `#` is a comment. An entry with no issue, or for a row that is not in
# the spec, is an error.
#
# Two modes. `cargo xtask check` (and `just check`) reports every finding of the rule as a
# warning: a gap that no line names, a missing fix, a missing pin, a stale line, and a malformed
# line. So the `docs` commit that adds a row can pass before the `test` commit that adds its lines.
# `cargo xtask spec-texts --strict`, which `just ci` runs, makes every finding an error: add or
# remove the lines in a `test` commit.
