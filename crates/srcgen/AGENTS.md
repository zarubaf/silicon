# Srcgen

## Purpose

The `srcgen` crate is the source generator of `cargo xtask diff-si`. It is a dev-only crate. No shipped binary depends on it. It comes after `syntax` and before `parse` in the layer order, so it cannot use the code of the stages that it tests. See [ADR 0018](../../doc/adr/0018-source-generator-crate.md) and [the front end design](../../doc/design/2026-10-09-frontend.md), section 11.4.

## Owns

This crate owns the lift of a core design to a source program, and the map from core vectors to source vectors. The lift makes aggregate ports from a shape tape: it groups adjacent ports into a tuple, an array, or a record. It groups adjacent registers, and adjacent `let` values, the same way into one aggregate register or wire, except the registers of a memory block. A read of a leaf is `.N`, `[N]`, or `.fN`, and the group takes one `:=`. An array has the type of its widest member, and the lift resizes a narrower leaf. It makes a source memory from the core block of a registered read. The vector map lists the leaves in the port layout, not in byte order. It also owns the typed form of a generated program, its printer, and its static evaluator. Its builder makes random typed programs and their input lines. The programs hold the forms of slice 2: static containers, records, strings, lists, `mut` formals, function values, and `diagnostic` statements. `Program::records()` gives the record lines of `observe`: the line and the column, the emitted name, the frame, the message, and the value. It walks the top module in evaluation order, elaborates a child at its `instance` statement, and takes the positions from the printed text. A frame is the call of a function with a `mut` formal, and a `diagnostic` runs in no other function. A function can first call an earlier one. A record then has several frames. The walk finds each call in the body of its function. A value is any static value of section 7.1. A module parameter can have a finite type. Its argument is a plain integer or a conversion. It checks its tuples against the contexts of the builder. The twin of a typed program writes out each comptime construct of the program. A mutation of a typed program changes one site, and it predicts the first error code where the pass order makes that code certain. Its kinds reach `S002`, `S003`, `S005`, `S007`, `S008`, `S010`, `S011`, `S012`, `S016`, `S017`, `S018`, `S019`, `S021`, and `S022`. The kind `DuplicateBind` copies a binding. The kinds of `match` and enums change an arm, a tag, a binder, an argument, a pattern, or a payload. An arm goes, repeats, or moves, or a `_` joins a complete match. A tag repeats or does not fit. A binder repeats. A constructor or a pattern gets an argument more or less. A pattern gets another kind, or a literal that does not fit. An enum is compared with `==`, or called as a function. A static arm differs from another. A variant gets a payload of 65537 bits. A prediction of a pass 5 kind holds only at a site that always runs. A tag kind holds only where the top frame of a module uses the enum.

Slice 3 extends the typed mode only (front end design, section 11.4). The typed mode makes enums with up to four variants, tags in shuffled order, and tags that no variant declares. It makes static enum values (constructors, `E()`, `reinterpret`), enum ports of a module, registers, wires, and `let` values, and `match` on integers, Booleans, and enums with binders. A static `match` runs only its selected arm, and a hardware `match` joins hardware arms. The arms cover each value by construction: `_` is the last arm, and it is there exactly when the other arms cover fewer than `2^W` values. A top enum port has the vector entries `<port>.tag` and `<port>.payload`, listed by port name and then in packing order. The enum and match draws come from a side tape. A form that adds a statement leaves the main tape alone, and a form that replaces an expression shifts its later draws. The typed mode also makes helpers that take and declare resources, named `H<k>`. A helper takes `Reg`, `Wire`, `Input`, `Mem`, and list formals, and it binds them. It declares a `reg`, a `wire`, a `mem`, and an `instance`. It calls an earlier helper. It returns `()`, one handle, a tuple, an array, a struct of handles, or the data of a memory. The builder calls each helper at a statement of a module frame or at the root of a `let`. A list of handles comes with a loop that fills it and a call that binds it. These forms draw from a third tape. The readable names of handles live in a pool that only that tape sees. A program without handle forms is thus the program of the main tape alone. The twin inlines each helper and resolves each selection from a container. It has no list and no handle formal. No enum is a module argument. An enum argument has the digest form of the emitted name, and ADR 0024 does not give that form to the generator. No `diagnostic` has a handle leaf or a hardware leaf in its value. The text of a handle holds the core path with the call-site numbers, and ADR 0023 does not give these to the generator. The lift mode does not change.

Slice 4 extends the typed mode only (front end design, section 11.4). The typed mode makes port families `A<n>` and `Z<n>`. Their entries stand in a loop, in an arm of a `comptime if`, and at the top. An entry can have the type `()`. It makes `as` keys: a `String`, a computed `String`, a scalar `PortKey`, a `PortKey` that joins a family, and a core keyword. A helper `HP<k>` takes a `comptime` name or key and declares a port with it. The signature of a module holds a plan of these ports. A parent thus binds the input entries of a child and reads its output entries. The body carries the plan out at the start of its top frame. The port forms draw from a fourth tape. The values of entries and keyed inputs live in a pool that only that tape sees. The function `mix_port` mixes each of them into an output. The twin writes an entry as a scalar port `A0_3`, declares all ports at the start of its module, and lists the ports of the top. `Program::ports()` comes from that list, in the port layout. `Twin::input_line` and `Twin::output_line` map the vector lines between the layouts of the program and the twin. The mutation mode gets `KeyRange`, `KeyType`, `ScalarFamily`, and `BadName`, and the copy of an indexed declaration is `S019`. The generator predicts no core name (`<k>f`, `0k`): `validate` checks them. The typed mode also reads an output or an output entry of a child through a temporary container (#368). The container is a tuple, an array, a struct literal `Q<n>`, or the result of a helper `HT<n>`, for example `(Box(u),).0.h.q[k]`. A `:=` target cannot be a temporary, so these forms are reads. They draw from a fifth tape and join the pool of the port tape. A struct or a helper names `Instance[M, args]`, so it occurs only if every env of the caller gives the same plain arguments. The twin selects the instance out of the container by its own rule, and it keeps no struct and no `HT` helper. The typed mode also binds the inputs of a child, and its input entries, through a local `let`. The local holds a tuple, an array, or a struct of instances, as in `let l = (u, v); l.0.a[k] := x;`. The other slots hold other instances in scope. An array holds only instances of one type. The twin keeps the handles of the local. The lift mode does not change.

Slice 4b extends the typed mode and the mutation mode with `@field` and no other builtin. ADR 0018 holds for this part: the generator makes no query and no type value. A step of a static chain can read as `@field` with a base and a key. A record takes a `String` key. The key is a literal, a join with `str`, or a static name. A tuple, an array, and a list take a `Nat` key. The key is the ordinary index, a static name, or a call plus an offset. A pass after the bodies spells the reads and the `:=` targets of a child port as `@field`. The key is a `String`, a scalar `PortKey`, or an indexed `PortKey`. The child can stand in a local container or a temporary container. A group of statements makes the held key and the early key. A later key calls a function with a `mut` formal on the local that an earlier key read. In the early class, the function runs a `diagnostic`. The same chain is the place of a `mut` actual of a function on a `let mut` container. The evaluator holds the roots that a `KeyCall` writes back, and `Program::records()` finds a call inside the initializer of its statement. These forms draw from a sixth tape, the field tape. A program with no `@field` is the program of the other tapes alone. The twin has no `@field`: it folds each key and writes the ordinary selection. Eleven kinds of mutation change one `@field`. They give a key another type or a range that does not fit. They give a key of no field or port. They give a `String` or an enum as the base, or the name of a port as the key. They read an input of a child, or a family as a value. They give a scalar `PortKey` the index 1, or a `diagnostic` to the key of a target. The kind `EarlyStep` gives an earlier step a key out of range. One draw in six of those that pick no kind of ports picks one of them. A record group declares two structs of hardware data. It declares a wire, a register, or a `let mut` of the outer struct. A chain of two `@field` steps reads a leaf. The wire is a handle. Thus the first step reads its base as a handle. A call in the key of the second step tests the order of the charges. A group can pass a leaf to a helper with a `mut` formal, as an actual or as a receiver. A group can also make a chain with a call of the effect function in each key. The twin declares one wire, register, or `let` for each leaf. These forms draw from an eighth tape, the record tape. Five more kinds of mutation close the gaps of `@field`. A hardware local as a key is `S011`. A call that changes a root in the key of a target is `S016`. A target that selects in an integer is `S017`. An assignment to a port through a local container is `S010`, Port in a place. A read of a child as data through a container is `S010`, Instance as data.

Slice 4b part 2 adds the queries `@TypeOf`, `@typeInfo`, `@Struct`, and `@ports` to the typed mode and the mutation mode (ADR 0032). The builder chooses each type first, so it knows the answer of a query. A query node holds the text and the static result, and the evaluator reads the result. `build/reflect.rs` maps a drawn type to the scalars of `TypeInfo`. The generator has no function from an expression to a type. A query reads a hardware name, a static name, a type literal, a function, a generated record type, or a child. A child comes by its name or through a local container. A query stands in a `diagnostic`, in a width or a type position of a wire or a register, and mixed into an output. A type position pairs a name with the outputs: an output mixes in its `data_bits`. A generated record type is an alias, `type D0 = @Struct(...)`, and the identity of a type is the id of its draw. The list of fields is a literal, empty, built with `push`, or the fields of an earlier type or of a struct. A wrapper `W0` forwards each port of a module with a loop over `@ports`. A parent names it in the place of the module. The list of `@ports` comes from the signature and the plan of the child, in port-layout order. The twin writes each query as its result and each wrapper port out. The queries draw from a seventh tape. A query reaches the builders of the other forms through an exhausted tape. The mutation mode gets nineteen kinds of queries. They give an unknown builtin, a wrong number of operands, an operand that is no place, a domain, a string index, or a hardware value. They also give a value in place of a type, a port in place of an instance, and a builtin in a type position. Two kinds give a key a call with an effect or a mutation. The last kinds change the constructor, a name, or the argument of a generated record type. Two more swap two fields of an alias, and give an alias of a declared struct the constructor of that struct. A static `let` can hold a type or the `PortInfo` list of a child, as in `let N0 = @ports(u);`. The evaluator and the twin never read it. Each query that reads its name carries its own result. Thus the generator needs no type token. The roots of `@TypeOf` include an own output, a family entry, and a memory. They include a `let` with no type and a handle in a container. They include the field of a record register or wire with no read. A query operand is a place. Thus a temporary container is `S001` there, and the generator draws none (F32). A temporary container is a tuple, an array, a struct literal, or a call of `HT<n>`.

The static evaluator models only the programs that the builder makes. It works on the typed program, never on source text or on a syntax tree. It can reject a program that the language accepts, but it must never give a value that differs from the language. It does not resolve names, check types, compute `cost`, or lower to core IR. ADR 0032 lets it hold a type that the builder drew, and no other. A need outside these limits needs a new ADR.

## Invariants

- Only `[dev-dependencies]` and `xtask` name this crate. Check: `cargo xtask check` (rule `workspace-dev-only`).
- This crate does not depend on `parse`, `resolve`, `typeck`, or `elab`. Check: `cargo xtask check` (rule `workspace-layers`).
- Each design of `Config::source()` lifts to a program that lexes with no error, with any shape tape. Check: `cargo nextest run -p srcgen`.
- A core memory lifts only if it has the exact block of section 7.6. Any other shape is `Unsupported::Memory`. Check: `cargo nextest run -p srcgen`.
- Each memory, each aggregate kind, and each aggregate register and wire occurs in at least 10% of 256 lifted designs. Check: `cargo nextest run -p srcgen`.
- The builder of `typed()` gives no fault on the tested tapes. Each program lexes with no error, and each form of slice 2 occurs in at least 10% of 256 programs. Check: `cargo nextest run -p srcgen`.
- Each form of enums and `match` occurs in at least 10% of 256 programs. The forms are the item and the static forms. They are the ports, registers, and wires, and the static and hardware matches. They are binders, nested matches, complete matches without `_`, a finite match, and a hardware match over a constructor. The text of a program, the arms of a match, and the tags of an enum stay within fixed caps. Check: `cargo nextest run -p srcgen`.
- The builder calls no function that runs a `diagnostic` in a width, a `const`, a struct argument, a parameter type, or a hardware arm. Check: `cargo nextest run -p srcgen`.
- A type expression that reads a mutable root is not reused after a write to the root. Check: `cargo nextest run -p srcgen`.
- The records of `Program::records()` come from the contexts of the builder, with no second identity rule (ADR 0018). The walk of the records and the builder reach equal tuples. The emitted names follow the rule of section 7.1, and the digest uses `sha2`. A parent record after a child record occurs in at least 1 program in 32 of 256. Both front ends accept each program, so the records before an error line have no prediction. Each shape occurs in at least 1 program in 32 of 256. The shapes are a record with two frames, each kind of value, a converted argument, and one identity under two spellings. A converted argument is the typed use of section 7.1 and changes only the identity and the name. Check: `cargo nextest run -p srcgen`.
- Each form of handles occurs in at least 10% of 256 programs, and a call of a helper that takes resources in at least 40%. A form counts at an executed call. The forms are the formals, the declared resources, and each shape of result. They are also lists, a `:=` through a container, and a child input that the caller binds. The last forms are a nested call, a repeated call, `read(h)`, and a read through a container. Check: `cargo nextest run -p srcgen`.
- A call of a helper that takes resources stands at a statement of a frame or at the root of a `let`. It never stands in an arm or a type. A program holds at most 6 helpers of the draw (`RES_HELPERS`), and one helper for an element may follow a helper of a list. A frame adds at most one more statement of handles (`HANDLE_STMTS`). Handle forms declare at most 24 resources in a program, and the budget checks the whole count of a statement before it makes the statement. A list holds at most 4 elements. A memory has 2 or 4 words of at most 16 bits. Check: `cargo nextest run -p srcgen`.
- Each register, wire, output, and child input of a twin has one `:=`. Each memory has one `read_port` and one `write_port`. Check: `cargo nextest run -p srcgen`.
- A deleted call of a helper with a handle formal predicts `S018` in the top frame of a module. A copy of a binding (`DuplicateBind`) there predicts `S018` too. Check: `cargo nextest run -p srcgen`.
- Each twin of a `typed()` program lexes with no error, and it has no comptime construct, no `match`, and no static name. It writes a hardware `match` as a chain of `if` expressions. Check: `cargo nextest run -p srcgen`.
- Each mutant differs from its program and lexes with no error token. A prediction holds on the slice-2 forms, or it is `None`. Check: `cargo nextest run -p srcgen`.
- A prediction of `ValueWindow` or of the four `S016` kinds holds only at a site that always runs. A condition of an arm is a port, a register, or the negation of one. Else the prediction is `None`. Check: `cargo nextest run -p srcgen`.
- A fixed set of 256 programs has at least 5 predictions of `S008`, 5 of `S016`, and 5 of `S021`. It has some of each other code of the kinds of `match` and enums. Check: `cargo nextest run -p srcgen`.
- A plan draws each public name once. A scalar name is `c<n>` or one core keyword. A family is `A<n>`, `Z<n>`, or `K<n>`. A key occurs once in its family and is below 32. A `PortKey` joins a family on a port of its direction. An entry or a keyed output has one `:=` in the block that declares it. A child input has one `:=` in its parent. A port stands only in the top frame, in a loop or an arm there, or in a helper that a `let` there calls. A module has at most 3 families, 4 keyed ports, and 4 calls of port helpers. A program has at most 24 ports. Check: `cargo nextest run -p srcgen`.
- Each form of ports occurs in at least 10% of 256 programs. A family entry occurs in 40%, an `as` key in 30%, and two keys of the top with different decimal and byte orders in 10%. A form counts at an executed declaration. Port forms occur in programs with handle forms at about their overall rate. The mean program stays under 6200 bytes. Check: `cargo nextest run -p srcgen`.
- A read of a child through a temporary container occurs in at least 10% of 256 programs. So does each container. The containers are a tuple, an array, a struct literal, and a helper result. - A program with no query text has the text that it had before the queries. Each form of queries occurs in at least 10% of 256 programs. Each kind of type, each root, and each tag occurs in 1 program in 32. A wide result occurs in 30%. No type reaches a record, the probe, or the argument of a module. A twin has no `@`. Each kind of query mutant gets at least 5 mutants, and at least 5 predictions if it predicts. The text of a program stays below 17 KiB. Check: `cargo nextest run -p srcgen`.
- Each group of records of hardware data occurs in at least 10% of 256 programs. A record wire, a record register, and a `mut` actual of a leaf each occur in 1 program in 32. A chain with a call in its key occurs in 1 program in 32. So do a chain with two key calls, a `let` of a type, and a `let` of a port list. So does each root of `@TypeOf`. A program with no record and no query has its pinned text. A draw of the field lane and of the record lane stays on its tape. Each gap kind gets at least 5 mutants, and at least 5 predictions if it predicts. Check: `cargo nextest run -p srcgen`.
- Non-test code has no `unwrap`, no `expect`, and no panic on user input. Check: `just clippy`.

## Dependencies

This crate uses `syntax` for the lexer, `core-ir` with its feature `gen`, `num-bigint`, `sha2`, and `proptest`. Its only normal user is `xtask`.

## How to test

Run `cargo nextest run -p srcgen`, then `just check` from the repository root.
