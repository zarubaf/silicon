# Silicon v0.1 language proposal

This reference preserves the language proposal from the prototype. It is input for the new language design, not the implemented specification. Only the language reference and [grammar](SILICON_GRAMMAR.ebnf) are included. Library proposals, examples, tutorials, and design history are outside this import.

<!-- vale off -->

**Status: proposed, not implemented.** This document and `SILICON_GRAMMAR.ebnf` define a candidate future language. “Must” describes a conforming future implementation, not a claim about this repository today. Examples use proposed syntax. The goal is a small language for explicit synthesizable circuits, deterministic generators, and independently authored executable Lean contracts.

## 1. Execution model

Silicon has elaboration and hardware stages. Host programs and proof checkers are external tools. Elaboration executes finite generator programs and constructs a typed graph; hardware evaluates that fixed graph and updates explicit state. There is no scheduling from software algorithms into cycles, implicit state, dynamic hardware allocation, or host instruction in a circuit.

Values have static, hardware-reference, or resource leaves; container shape is known during elaboration and is separate from its leaves' stages:

- Static leaves are mathematical integers, fitting typed finite integers, Booleans, strings, types, and named functions. A value is **recursively static** iff all its leaves are static.
- Hardware leaves are typed graph references. A graph constant remains a reference, not permission to inspect an arbitrary reference.
- Resource leaves are Domain, Wire, Reg, Mem, Instance and Input handles, with identity and ownership. Builder containers (arrays, tuples, records, lists) may mix static, reference, and resource leaves. Their length/index/field structure is known independently of leaf values; known shape does not make contents recursively static.

Every statement executes during elaboration. Ordinary `let` and local assignment bind or replace builder values; they do not update hardware state. `comptime` parameters and pure-static function arguments require recursively static contents. Branch conditions, bounds, widths, and type arguments require the corresponding static scalar/type. A signal or resource cannot become a static integer or Boolean, even if an optimizer could prove it constant. Literal constants can be lifted into hardware at a typed use.

`fn` is an owner-sharing helper; `comptime fn` is a static computation with no hardware/ambient inputs. The latter rejects nested hardware/resource leaves and graph operations, but may emit diagnostics and mutate recursively static caller places through mut formals. Static purity does not promise a result-only function. Calls with mut formals execute their place writes on every invocation; function-result memoization must not skip them. A whole-build cache may restore the complete frozen build result and ordered diagnostic transcript, under the normal exact identity checks. A generator may compute static results, construct combinational expressions, allocate resources, bind drivers, or capture instances. Effects are inferred transitively at each specialization. In a hardware conditional, calls must have only combinational effects: no allocation, port declaration, instance capture, driver/update binding, diagnostic emission, or mutation of caller bindings. Mutation of local copied builder values created within the hardware arm is permitted; changing a binding that existed before that arm began is forbidden, including through nested mut helpers. Resource reads are combinational; := and memory-port bindings are graph construction effects. No effect may be hidden behind a function value.

`comptime if (c) { ... } else { ... }` executes only its selected branch. Both branches must parse; only the selected branch is specialized and type checked. `comptime for i in a..b` enumerates static integers in the half-open interval in increasing order; an empty interval executes nothing. Recursion supports other finite structural algorithms; there is no `while`, `break`, or `continue`. Evaluation is deterministic and budgeted: exceeding declared steps, recursion, integer size, collection size, or graph size is an elaboration error, never partial success. Budgets are build inputs and evidence records.

Elaboration executes statements in source order. Calls and postfix expressions evaluate their callee/base first; operands, arguments, indices, and aggregate constructor/array/tuple elements then evaluate exactly once, left to right in source order, obtaining value copies at that point. The operation applies after its required values are available. A comptime-for evaluates its bounds once, lower then upper, before iteration. Static `&&`/`||` skip the right operand when the left determines the result; static conditionals evaluate the condition then only the selected branch/arm. Hardware conditionals evaluate the condition then both pure arms in source order; hardware logic evaluates both operands. This elaboration order does not change simultaneous old-state hardware updates.

`if (condition) { value } else { value }` is a pure expression. With a hardware condition, it constructs a mux, analyzes both arms, requires identical result types, and cannot make graph shape depend on the signal or change resource ownership. With a static condition it selects one value. Blocks in this expression contain exactly one expression, not statements. `static_assert(c, message)` requires static Bool; `error(message)` terminates elaboration with a static String diagnostic. Neither grants a runtime assumption.

## 2. Source, declarations, and types

Files are UTF-8 `.si` source namespaces; module means a hardware component, not a source file. Identifiers are ASCII and case sensitive. The grammar defines all lexical and precedence rules. Module/function/type items are declared before execution, so textual declaration order does not affect lookup. Locals have lexical scope, cannot shadow another binding in the same scope, and must be defined before use. A block can shadow an outer local. There are no implicit globals or mutable source-global variables.

Each source file has one item namespace; duplicate item names, including import aliases, are errors. Parameters share their function/module's outer local scope and cannot duplicate each other. Prelude primitive/type bindings cannot be redeclared or shadowed. A function returning Unit may fall through or use return; other executed paths return the exact helper result type. Function returns never declare ports or expose a hardware interface. Modules have no return/arrow; only input/output declarations define their complete ABI. Top-level `const` evaluates statically without graph or diagnostic effects, including through callees.

`pub` exports a declaration; declarations are otherwise private to their source namespace. `import pkg::module as local;` imports one source namespace under an explicit lexical alias; qualification is `local::name`. Imports never copy declarations into the local scope. There are no wildcard imports, macros, traits, implicit coercion searches, or operator overloads.

Every function parameter and result has a type. Ordinary fn helpers share their caller's hardware context/owner; only module declarations form hardware boundaries (§4). Static parameters carry comptime; ordinary helper parameters accept typed builder values, including references/resources and containers. Pure-static function parameters, including the contents of mut places, are recursively static. A type expression can refer to earlier static parameters. Calls use positional arguments; static arguments are written explicitly. Named functions are static values. A function-value type `fn (T, U) -> V` describes a specialization without remaining static parameters. Its arrow binds right: `fn () -> UInt[8]` returns UInt[8]; an outer application requires parentheses around the function type. Passing a generic function requires a named wrapper with its static arguments fixed and that signature; there are no closures or hardware function pointers.

Type expressions may call pure-static type functions, for example a record field of type `optional_meta(M)`. Such computation must return Type and have no diagnostic effect; type-family arguments and annotations cannot emit diagnostics. This uses the ordinary evaluator without type-dependent parsing.

Plain let and ordinary parameters are immutable; let mut creates a mutable builder binding with fixed declared/inferred type. Assignment = replaces a value of that type, recomputing stages/tags; it never updates hardware. Places are mutable local roots with static in-range array/list/tuple indices or record fields; no string/resource-internal place exists. Collections copy by value (sharing/copy-on-write may implement that); copied resource handles retain identity, never allocate or deep-copy storage.

A mut formal is a nonescaping alias of a caller's exact-typed mutable builder place. It may replace that place; no implicit read applies to it. Such parameters are allowed only on helpers; module constructors are recursively static and have no mut formals. A root becomes pending before its indices evaluate; resolve the complete mutable place before remaining arguments; reject overlapping roots among mut actuals and any other mutation of a pending root while evaluating arguments. The alias lasts only for the call and can be passed onward within it; returned ordinary values are copies. Assignment likewise selects its destination before RHS and rejects other root mutation until commit. Each completed operation releases this restriction. This general rule covers push/pop and user helpers; xs.push(xs.pop()) and xs[0]=xs.pop() reject, whereas two successive pop call arguments are legal.

Implicit reading is contextual, never allocation. Unannotated let a=q preserves Reg[T]/Wire[T]; let a:Reg[T]=q preserves identity, while let a:T=q reads its data. Typed helper data parameters, constructors, assignment RHS and returns read a matching Reg[T]/Wire[T]; resource-typed and mut formals retain handles. Operators/conditions and data field/index selection read Reg/Wire. Own input/output names and child outputs are data references; Input handles are target-only and never implicitly read. Conversion recurses through matching array/tuple shapes, but never changes a nominal record type: construct an explicit data record from a handle record's fields. Resource destinations for := remain raw, including handles selected below builder containers; selecting a stored payload field is not a separate resource. Mem/Domain/Instance are never implicitly read. Diagnostic inspection stays raw. Explicit read(handle) remains available.

A syntactic receiver call x.method(args) resolves method as one ordinary function in the lexical item/prelude namespace, not a trait/type search. Insert the receiver after its leading comptime formals, whose arguments remain explicit: xs.append(T,v) means append(T,xs,v). The receiver evaluates/resolves first, then explicit arguments left to right; a mut receiver uses the same pending-root rule. Prelude xs.push(v), xs.pop() and xs.len() use their existing type-directed collection signatures. To call a function-valued field, write (obj.field)(args); obj.field(args) always denotes the lexical receiver helper. There are no overloads or implicit generic inference for user helpers.

```silicon
pub fn add(comptime W: Nat, a: UInt[W], b: UInt[W]) -> UInt[W] {
    return a +% b;
}

pub fn product(comptime A: Nat, comptime B: Nat,
               a: UInt[A], b: UInt[B]) -> UInt[A + B] {
    return resize(UInt[A + B], a) *% resize(UInt[A + B], b);
}
```

Static `Int` is an arbitrary precision signed integer; `Nat` is its nonnegative subtype, checked at annotation boundaries. `String` and `Type` exist only statically. A type can be passed to or returned from a static function. Static `Bool` has values `true` and `false`. Hardware data has three scalar types: `Bool`, `UInt[W]`, and `SInt[W]`, with static `W >= 1`. `Bool` supports logical operations, not integer arithmetic; `UInt[1]` is an integer, not a condition. `SInt[W]` interprets its W bits in two's complement. A raw bit vector uses `UInt[W]`; `Bits` is a library spelling with no distinct semantics.

Aggregates are fixed arrays `[T; N]`, tuples `(T, U)`, and declared records. `N` is static and nonnegative. Tuple elements use `.0`, `.1`, etc.; record elements use declared field names. Fields and elements retain their own stages/domain tags. Arrays are homogeneous. `Unit`, written `()`, has no leaves. A hardware data type is recursively Bool, positive-width UInt/SInt, Unit, or an array/tuple/record of hardware data types. This validates declared element/field types even when cardinality is zero: `[String;0]`, `[Reg[UInt[8]];0]` and `[UInt[0];0]` are not hardware data. Empty hardware aggregates are allowed at ports, but reg/wire/mem require nonempty data. Instance/Input are resource types, never hardware data or recursively-static constructor values. Struct declarations may take only static parameters; `Packet[W]` specializes a struct, and `Packet[W](field0, field1)` constructs it in declaration order. Constructors check field types and argument count. Type aliases are transparent. There is no recursive hardware type, pointer, reference address, dynamically sized hardware collection, or enum encoding primitive; tagged unions can be records of explicitly encoded integers and data.

Declared records are nominal: identity includes defining package/source namespace/declaration and static arguments. Arrays and tuples are structural. Type equality is equality of those normalized identities after transparent aliases. Hardware storage packing places array index zero, tuple element zero, and record's first field in the least significant bits, recursively; Bool occupies one bit. Host ABI packing is separately byte aligned. Types containing resources, functions, lists or other static-only leaves cannot be hardware data. `T()` constructs the static recursive zero of any data type; finite scalar `T(n)` accepts a fitting static literal/value, and aggregate field constructors retain the stages of their arguments. Typed finite static constants use the same finite operations as hardware but evaluate statically; lifting them creates graph constants. There is no reverse conversion from graph constant to static value.

`data_bits(T)` requires a static hardware data Type and returns static Nat: Bool=1, integer=W, Unit=0, array=N times element size, tuple/record=sum of field sizes. It validates the complete type before counting. This type-size query exposes no runtime bits, handles or graph structure; the bounded structural queries below expose static schemas. Same-type empty-data equality is constant true and domainless.

The five @ builtins are compiler operations, not extensible macros. Their metadata uses these ordinary prelude records (fields are not optional or variant payloads):

```silicon
struct FieldInfo { name: String, ty: Type }
struct TypeInfo {
    kind: String, fields: List[FieldInfo], element: Type,
    length: Nat, width: Nat
}
struct PortKey { name: String, indexed: Bool, index: Nat }
struct PortInfo { key: PortKey, ty: Type, is_input: Bool, domain: String }
```

`@TypeOf(x)` returns the exact raw Type of an existing typed binding/selection, without implicit reading. Thus a register's type is Reg[T], and a selected child input's is Input[T]. The operand is an identifier, parenthesized operand, field/static-index chain, or @field selection rooted in an existing binding; calls/factories/arithmetic value expressions reject. Resolve only those existing selections and their pure-static keys/indices, with no function-call, diagnostic, mutation or graph effect in that resolution. No value is sampled or graph read allocated: @TypeOf(q.field) resolves its data field type without executing read(q). `@ports(h)` uses the same operand/resolution restriction and requires an existing same-owner Instance handle; it never instantiates one.

`@typeInfo(T)` returns static TypeInfo. Exact kind tags are bool, uint, sint, unit, array, tuple, record, int, nat, string, type, function, list, domain, reg, wire, mem, input, instance. All irrelevant fields are fields=list(FieldInfo), element=Unit, length=0, width=0. Bool sets width=1; finite integers set width=W. Array sets element/length; tuple/record set ordered fields and length=field count. Tuple field names are canonical decimal 0,1,...; record names are exact declared/generated names. List/Reg/Wire/Mem/Input set element to their element/payload Type, and Mem sets length=depth. Other kinds retain defaults; Instance metadata exposes no ports, private state, constructor fields or actual domain maps. Aliases normalize. The metadata is structural; equal field lists do not equate nominal Types.

`@Struct(fields)` accepts a recursively-static List[FieldInfo] or fixed [FieldInfo;N] sequence (including @Struct([]), contextually [FieldInfo;0]) and returns a structural generated record Type. Names must be distinct ASCII identifiers excluding keywords; field Types must be well-formed and nonrecursive. Empty fields are valid. Identity is the ordered sequence of names and exact normalized field Types, independent of collection kind or construction site; declared struct identity stays nominal. @Struct(@typeInfo(Nominal).fields) is therefore not Nominal. Builder/resource fields are permitted under ordinary stage/ownership rules, but T() zero exists only for hardware data: no uninitialized/generic default builder value is introduced. Existing positional field constructors still apply. @typeInfo/@Struct evaluate their static arguments left-to-right in a structural context: no graph/diagnostic/pre-existing-place mutation effects, although a called static helper may mutate its own fresh copied locals. All computations are budgeted; no source query instantiates hardware.

`@field(x,key)` is computed selection, not a metadata query. For records key is static String; for arrays/Lists/tuples it is static Nat; for Instance it is a scalar-name String or PortKey. Tuple descriptors' decimal names are not tuple keys. Evaluate base once, then key once, in normal expression order; existing typed data contexts read Reg/Wire payloads before data selection, while raw builder fields retain their selected leaves. Instance selection rechecks the actual public port: inputs remain target-only Input[T], outputs remain data, private/missing keys reject. A scalar PortKey requires index=0; an indexed key names that exact sparse family entry. A forged descriptor does not grant access or a direction/type change. In a mutable place/mut argument, preserve the original root, require a builder place and lock it before evaluating the key; pending-root/overlap/whole-binding rules apply exactly as ordinary selection. In := destinations resolve raw handles/Input/own-output targets; a stored payload field or aggregate-port element is not a separate endpoint. Selection cannot change owner, tag, storage identity or nominal Type.

@ports returns static List[PortInfo] in public basename/numeric-key order, including empty ports, with payload ty and direction; it excludes private resources and clocks/resets as data ports. domain is the declared symbolic domain-formal name (also through same-owner aliases), or empty String for an unannotated combinational port; it reveals no resolved Domain/reset/owner/graph value. Domain aliases retain that declaration provenance rather than inferring formals by comparing mapped clocks. A wrapper receives the actual Domain mapping separately: equal formal-name strings never prove equal clock/reset identities. Existing tags and complete binding/capture checks remain authoritative.

`List[T]` is an elaboration-only finite growable list. `list(T)` creates it; `push(xs, x)`, `pop(xs)`, and `len(xs)` manipulate its structure. `push/pop` require a mutable local list place and mutate that place; ordinary assignment and argument passing copy collections structurally, preserving referenced hardware/resource identities. Pop on empty is an error. Collections cannot contain themselves. Fixed array literals `[x, y]` require one type and have fixed length; `[]` requires a contextual zero-length array type. Array/list indexing requires an in-range static Int/Nat index; a hardware index is rejected. Runtime selection is constructed explicitly by library mux trees or memory ports. Data field/index selection reads a register or wire before selecting; builder-container selection instead preserves its selected raw leaf until a data context requires it. `len` returns static Nat for arrays, lists and strings. Static strings support concatenation with `+`, indexing by Unicode scalar (returning a one-scalar String), and `str(n)` canonical signed-decimal conversion from Int/Nat; these have no hardware meaning.

This ordinary helper accepts a known-shape list of caller-owned registers. Passing that same list to a comptime formal/pure-static function rejects its resource leaves; passing it to a module constructor rejects nonstatic contents recursively.

```silicon
fn bind_all(rs: List[Reg[UInt[8]]], x: UInt[8], en: Bool) -> Unit {
    comptime for i in 0..rs.len() { rs[i] := if (en) { x } else { rs[i] }; }
}
```

## 3. Arithmetic and combinational semantics

Finite integer operations require identical width and signedness; there is no contextual resizing of an existing hardware value. Literals are static integers until a typed use. At a finite typed use a literal must fit the destination's numeric range. Thus `UInt[8]` accepts 255 but rejects 256 and -1; `SInt[8]` accepts -128 through 127. Bool literals require Bool context. Aggregate constants are checked recursively.

Finite UInt/SInt `+%`, `-%`, and `*%` return the operand type, with the low W bits of mathematical addition, subtraction, or multiplication. Their all-static operands produce a typed finite static result; otherwise they construct hardware. Signedness changes interpretation, not these modular bit patterns. Unary `-` on finite integers is modular negation; `~` flips exactly W bits. Ordinary `+`, `-`, `*`, `/`, and `%` accept only mathematical Int/Nat, never finite integers even when static. Mathematical operands promote to Int and produce Int; a Nat destination separately checks nonnegativity. These operations do not wrap. Division truncates toward zero; remainder is `a - (a / b) * b`; division by zero is an error. Static String `+` is concatenation. Hardware division is an explicit library architecture. Unary `+` is absent.

Integer `&`, `|`, and `^` operate bitwise, retaining finite operand type; mathematical Int/Nat operands promote to Int and use infinite two's-complement interpretation, as does mathematical `~n = -n-1`. `!`, `&&`, and `||` accept only Bool. Hardware logic evaluates both operands; there is no effectful short circuit. Static `&&`/`||` short circuit. Equality compares values of the same data type, including all aggregate leaves, and returns Bool; static Int/Nat share mathematical integer comparison. String and Type equality is static. Functions and resources have no equality/ordering operators. Integer ordering is unsigned for UInt and signed for SInt; Bool has no ordering. Ordering and aggregate equality require a compatible domain for their result.

Finite shifts take UInt/SInt on the left and UInt or a nonnegative static Int/Nat count on the right, retaining the left type. `<<` inserts zeros and discards high bits; `>>` is logical for UInt and arithmetic for SInt. At amounts >= W, left shift and UInt right shift produce zero; SInt right shift produces all sign bits. All-static finite operands evaluate these same finite functions. A hardware UInt count may have any positive width and is not truncated to `log2(W)`. Mathematical Int/Nat shifts require a static Int/Nat nonnegative count and produce Int: `a << k = a * 2^k`, `a >> k = floor(a / 2^k)`, without clipping. Thus `1 << 8 = 256` and `-3 >> 1 = -2`. A mathematical left operand with a signal count rejects; negative counts always reject.

`resize(T, x)` requires finite integer source and target with equal signedness. Widening zero extends UInt and sign extends SInt; narrowing drops high bits, explicitly modulo the destination width. `reinterpret(T, x)` changes UInt/SInt interpretation at equal width without changing bits. Both preserve static versus reference stage. Slicing, concatenation and Bool/UInt[1] conversion are explicit library functions, derived from these casts, shifts, comparisons and muxes; they are not additional compiler primitives. No general integer truthiness exists. The primitive rules operate equally on width one.

Combinational expressions denote total two-state functions. X/Z, tri-state buses, real numbers, analog timing, and undefined arithmetic are outside v0.1. A target may reject a design it cannot lower while preserving these semantics. Hardware cost reports may identify primitive operators and instance paths; they do not change arithmetic or proof meaning.

## 4. Domains, graph resources, and state

A module has only explicit comptime constructor parameters, requiring recursively-static values; no data/resource constructor arguments or return exist. `instance child=Module(staticArgs...) [with {...}];` is a named declaration yielding a parent-owned handle, never an expression or function call. Only modules/extern modules can be instantiated. Ordinary fn helpers may declare resources, ports and children in their caller's owner and return ordinary builder values; they never acquire a capture/proof boundary.

Module domain formals are immutable bindings sharing the parameter scope. Omitted domains(...) means domains(clock), one default; domains() is combinational with no clock/reset pins; one named formal is default and several have none. Roots bind rising clocks/active-high synchronous resets. Domain identity includes complete clock/reset/policy, not frequency/name equality. Constructors cannot hide Domain handles. Child mappings resolve before static arguments: one formal inherits an unambiguous parent default or a complete explicit override; several require a complete named map. Duplicate/unknown/missing names reject. Helpers inherit their current module frame, without parent ambient domains or a new default from argument order. Asynchronous-reset integration and creating a Domain from a native or foreign generated/gated clock are deferred beyond v0.1. Domain events are externally supplied for declared, explicitly mapped root domains. Qualified foreign resetless state follows §8; native reg retains mandatory synchronous reset. No foreign interface creates a Domain or changes event meaning. Maps/policies are frozen evidence.

`input name:T [in d] [as key];` and `output name:T [in d] [as key];` declare the sole hardware interface. T is recursively valid hardware data, including declared types at zero cardinality. One-domain ports default to it; multiple-domain ports require in d; a root combinational input is Comb. Inside its module, an input is read-only data, and an output is data in expressions but its declared name is a binding target for :=. No first-class own-output target is exposed: copying that name copies data. The immediate parent selects child.name: inputs yield Input[T] targets; outputs yield read-only T data. Internal registers, wires, memories, domain bindings and descendants are inaccessible. Root inputs have external drivers; every other input and every output needs exactly one complete binding, including empty ports. Empty bindings preserve logical identity but allocate no Wire/Reg; missing/duplicate bindings still reject. Foreign outputs are bound by their exact locked model/artifact.

`input request[i]:T;`/`output response[i]:T;` declare one whole port at a static Nat key. A family is a namespace of finite sparse keys, not an array/value/collection; bare families and len queries reject; @ports enumerates only an existing instance's complete public port descriptors. Static selection must name a declared key. Entries may have different data types/domain annotations but one family direction. Scalar/aggregate name versus indexed family, duplicate key/direction and reserved domain-name conflicts reject. Public names default to their identifiers/keys, also when declared by helpers; helper frames never alter their selectors. Optional as separates a scalar local binder from its computed public key: key is a static String or PortKey, with the same name/key validation and collision checks. Local pin remains its input data/output target; parent selection uses the public key. An indexed source declaration cannot also use as; use scalar pin as an indexed PortKey instead. Key computation has the same structural-context effect limits as @Struct. An empty loop declares no family entries. Explicit zero-length aggregate ports retain names/type/shape instead. `output response:[T;N]` is one endpoint: response\[i\]:=x is forbidden partial payload binding; a separately declared response[i] endpoint has its own complete binding.

Complete input/output port schemas sort by ASCII basename and then numeric family key; payload fields retain declaration/index order. Input records prefix reset leaves in root domain-declaration order; event bits use that order. Empty ports remain in schema, with zero data octets and no sampling tag, but input declaration domain context remains. Internal resource/instance identity uses source paths: owner, declaration identifier, helper defining namespace/call-site byte span, enclosing scope spans and loop binder/value frames. Recursion appends call-site frames; no global gensym is needed. Segment kind/payload tuples are encoded injectively by UTF-8 byte lengths and bytes. Aliases never rename/reinstantiate. Duplicate resource identities reject. Optional frozen external port-name maps are collision-free bijections included in identity/schema, not allocation or proof authority.

`Instance[Module,staticArgs...]` names the exact module declaration identity and normalized, copied constructor values (including Types/function identities and List contents). Arguments snapshot left-to-right before later mutation; the handle's type/identity never follows changes to caller containers. Resolved domains/owner/instance path are handle metadata. `Input[T]` identifies one exact child-input endpoint owned by its immediate parent. Both are nonstatic builder resources: homogeneous containers require exact types; heterogeneous handles use tuples/records or per-iteration specialization. Copies retain identity/permissions. Ordinary helpers can accept/return them only within that current owner, including a locally created child handle. They cannot cross module constructors/ports or move to another owner; input aliases cannot bypass single binding. `fn bind(comptime T:Type,p:Input[T],x:T)->Unit { p:=x; }` is an ordinary same-owner helper, not a connect primitive. Input is target-only, including Input[Unit]; read(child.input) rejects.

`reg q:T [in d]=resetValue;` creates a fresh immutable Reg[T] with fitting static reset value; `wire w:T [in d];` creates Wire[T]. T is nonempty hardware data. Domain selection uses the module default; an unannotated zero-domain wire has a symbolic tag derived from its completed driver, whereas a register requires a declared domain. reset(d) reads reset; reset() uses an existing default. Same-owner helpers may return their locally declared handles; module ports never export them.

`destination:=value;` binds one complete Wire, Reg, own output or Input endpoint. Raw resource handles may be selected below builder fields/indices. Stored payload projections q.field reject; bind the whole value. RHS uses exact typed data conversion/domain checks. Register updates occur at every non-reset domain edge; q:=if(en){value}else{q} expresses hold. Reset overrides that equation; all equations read old state. Missing/duplicate bindings reject even through aliases/repeated statements. A wire/output never latches; no last-wins or statement priority exists.

Every nonconstant scalar reference has Comb or a resolved Domain tag; constants are neutral. Combining constants with one tag is allowed; distinct Domains or Comb with a Domain reject. Aggregates retain per-leaf tags. Clocked inputs/wires/registers/outputs validate tags against their mapped/declared domains, never retag a crossing; constants fit that declared domain. A combinational child elaborates against symbolic input tags, then derives each from completed parent input equations, with constant actuals neutral. Its operations/outputs and unannotated local wires propagate those eventual tags; separately tagged leaves may forward but cannot combine. Tag constraints and cycles close before acceptance/certification, independent of construction/binding order. Root Comb inputs remain Comb; signals never become static through this process. Memory address/data/enables and reset expressions obey the same checks.

```silicon
pub module Counter(comptime W: Nat)
    conforms demo::CounterStatus(W) using demo::CounterStatusProof(W) {
    input enable: Bool;
    output value: UInt[W];
    output full: Bool;
    reg count: UInt[W] = 0;
    count := if (enable) { count +% 1 } else { count };
    value := count;
    full := count == UInt[W]((1 << W) - 1);
}
pub module Main() {
    input enable: Bool;
    output value: UInt[4];
    instance counter = Counter(4);
    counter.enable := enable;
    value := counter.value;
}
```

Elaboration creates each child against symbolic declared inputs; after complete parent wiring closes, captures freeze exact static arguments, domain maps, complete port schemas/equations, full output/state projections, hierarchy and original source closure. Unconsumed child outputs remain observed by its contract. There is no separate result ABI or ordinary fn capture. Module identity is its defining source declaration; an instance handle identifies that scoped child, while a selected output is signal data.

After elaboration the compiler checks complete drivers and updates, ownership, types, domain compatibility, unique source identities, and every combinational strongly connected component. Registers and memory read registers break dependency paths; ordinary wires and combinational foreign outputs do not. Any remaining combinational cycle is an error, including cycles across child instances. There is no inferred latch: incomplete assignment is rejected. Intentional level-sensitive latches are deferred because transparent intervals, clock phases, race/CDC reasoning, and target constraints would enlarge the semantic and proof core.

The model state is all native registers, memory words, memory read response registers, and the declared state of foreign digital models. An event contains an explicit subset of domain identities. `eval(S, I)` computes outputs from old S without an event. `step(S, I, E)` first computes the same outputs, then commits all resources in E together from old S; other domains hold. An empty E is a valid hold step. Simultaneous edges are simultaneous, not ordered by names. Reset signals affect only selected edges and never mask pre-edge outputs automatically. An event schedule is a digital abstraction, not a model of metastability or analog time. Foreign state follows this same protocol with declared domain ownership and reset behavior (§8).

Simulation's designated start uses native register reset values, zero native memory words, reset native read response values, and each foreign model's declared designated start. This is a tool convention. Physical power-on is arbitrary unless external technology evidence establishes initialization. Specifications must distinguish correctness from the designated simulation start, correctness from an established relation, and correctness on the suffix following an actual reset. A reset edge does not justify an equality about its already observed pre-edge output.

## 5. Memory primitive

The sole RAM declaration is `mem words:[T;N] [in d];`, producing Mem[T,N] with source-derived name and the same domain selection as reg: N >= 1 words, one synchronous read port, one synchronous whole-word write port, one domain. T is a nonempty hardware data type. There is no implicit array-to-RAM conversion. Address type is UInt[A], where A = max(1, ceil(log2(N))). Each memory requires exactly one `read_port(m, address, enable)` and one `write_port(m, address, data, enable)` binding. Calls may use constant false enables. Missing or duplicate port bindings are errors, independent of whether their enables could overlap.

`read_port` returns the current `(data: T, valid: Bool)` response registers; its address and enable bind the next edge's request. `valid` is a completion pulse on the observation following an enabled, in-range read. Data holding does not imply a valid new completion. On a selected non-reset edge:

- Enabled, in-range read: next data = old memory[address], next valid = true.
- Enabled, out-of-range read: next data = zero(T), next valid = false.
- Disabled read: data holds, next valid = false.
- Enabled, in-range write: that word takes the supplied data. Otherwise all words hold.

A simultaneous read and write of the same word reads the **old** word. This applies at depth one. There is only one writer, so write/write priority does not exist. On reset the read response becomes `(zero(T), false)`, both requests are cancelled, and stored words hold. RAM contents are not cleared or presumed initialized by reset. The zero function maps each integer to zero and Bool to false recursively. OOB behavior includes real guard logic; a backend must emit guards and any collision emulation needed, or reject the target mapping. It may not assume the macro's undefined behavior is equivalent.

Byte masks, asynchronous reads, extra ports, mixed clocks, initialization images, and target-specific collision modes are not memory primitives. Libraries may implement forwarding or banked/multipumped architectures with explicitly different interfaces and proofs. A read-first memory plus an output register requires a FIFO head cache or correctly aligned bypass when a simultaneous enqueue becomes the next head. Occupancy alone does not establish that an arriving RAM response is the new logical head. The standard FIFO contract makes that obligation explicit.

## 6. Packages and reproducibility

A build selects one entry module, exact static arguments, language version, semantic options, and a dependency lock. Package identity is a content identity, separate from a local alias or directory spelling. The declarative package manifest lists its name/version, source root, exported source namespaces, Lean modules, dependencies by alias, and foreign hardware artifacts. The lock records each transitive package's exact content digest and version/revision plus toolchain identities. v0.1 has no source build scripts or automatic version solver: dependency acquisition/lock editing is a separate tool operation.

`pkg::m` resolves only through the caller package's locked alias table and declared source namespace map. Imports cannot escape package roots, including via symlinks. Missing/private source namespaces, duplicate aliases/public identities, import cycles, unpinned dependencies, or changed locked bytes are errors. No fallback extension guessing occurs. Imported functions/modules retain their defining source namespace's lookup environment, even when called through another package's alias.

Elaboration cannot access files, processes, environment variables, network, wall clock, randomness, native pointers, or foreign code. Its only output effect is the deterministic diagnostic sink in §9. The loader reads only the closed manifest-selected source/artifact set before evaluation. External generators may produce a source package of constants before locking; that output becomes an explicit hashed input, not an ambient elaboration effect. Host and proof execution use separately recorded closures. Dependency bytes are frozen for the build; changes while elaborating or checking invalidate it.

## 7. Independent Lean attachment and composition

Each selected contract descriptor chooses exactly one proof profile. The following five obligations define cycle refinement; event refinement uses the distinct §8 library profile, with its own theorem type and evidence label.

`conforms package::Contract(staticArgs...) using package::Proof(staticArgs...)` attaches a selected executable Lean contract and proof companion only to a module/extern module declaration. Ordinary fn has no hardware attachment/capture; helper lemmas are normal Lean library work. These references resolve through the locked Lean module map. Arguments are statically typed literals/values serialized by the binding schema, not arbitrary Lean text or tactics. Attachment is a request to check conformance, not an assertion granted by the parser. Unattached code may elaborate/simulate; it has no certificate.

The public binding schema is named, complete, and exact: Bool maps to Lean Bool; both finite integer types map to `BitVec W` with signed interpretation recorded; arrays, tuples, and records map structurally with ordered fields, including empty shapes. Static constructor Lists may determine declared shape, but never create automatic ports or dynamic hardware storage. UInt[1] maps to `BitVec 1`, never Bool. Input includes every data/reset leaf and the event subset for each domain; clocks are represented by events, not bit-valued data. Output includes every declared output port/leaf, including unconsumed and empty outputs in the sorted schema. The schema records widths, signedness, field names/order, domain identities, and observation timing. No port can disappear because a proof does not use it.

The tool emits an actual machine from the frozen elaborated graph: `State`, a designated simulation start, `step`, and `observe`. The independently authored specification has its own state, start, executable transition/observation, `allowed(specState, input)`, and designated `reset(input)`. Its transitive dependency closure must not reach generated implementation/capture/seal modules or selected proof-companion modules. This also excludes intermediates that import such authority. Shared independent foundations, ordinary pure libraries and specification dependencies remain allowed even when companions import them: `Spec -> Contracts/Std` and `Proof -> Spec/Actual/Contracts/Std` is legal; `Spec -> Library -> Actual` rejects. Proof sources may import both spec and actual. The checker binds the exact selected contract application, input/output ABI, and reset predicate to actual reset/events; a theorem about another specification is insufficient.

A cycle refinement supplies relation R(actualState, specState) and these checked obligations:

1. R holds between designated starts.
2. From R and `allowed`, one actual and one specification step preserve R.
3. From R and `allowed`, **all** actual outputs equal specification outputs before the edge.
4. From every actual state, a designated reset event establishes R to specification start, without `allowed` as a premise.
5. From every specification state, that reset event reaches its start, also without `allowed`.

The reset predicate must be exactly the complete reset event declared by the attachment: for a resettable multidomain contract this means all its state-owning domains edge with reset asserted. A component without such a reset event can obtain a start/relation-based refinement, explicitly labeled without after-reset guarantee; it must not substitute an unreachable or false reset predicate to claim reset conformance. Unreset RAM words can remain arbitrary while R abstracts unreachable/invalid entries. A RAM macro's raw contents generally cannot satisfy a reset-to-zero contract.

The generic lifting theorem derives full output trace equality only on traces satisfying `allowed` at every specification pre-edge state. After-reset equality starts at the next observation after the reset event. Static assertions do not discharge these predicates. Environments and parents must prove them, or retain them as explicit assumptions in the top theorem.

Children are checked before parents. A checked child exports its relation, preservation/observation/reset guarantees, exact ABI, and immutable model identity. The parent receives projections of that actual child's state, actual wired input, and complete output. To use its conditional guarantee, the parent proves R_child under its own invariant and proves `allowed_child` on the **captured actual input**, under parent assumptions. A suggested wiring equation is checked against that projection; source hints cannot replace it. The parent then proves its own preservation and full outputs. It may unfold unproved child implementation equations to prove the parent directly, but may not assume an unproved child specification.

For a general counter module with enable/increment inputs and value output, a unit-counter spec allows arbitrary increment when disabled and requires increment==1 when enabled. A parent binds literal one and discharges that condition. CounterStatus is a distinct full-interface contract including value and full, not that older single-output contract. A complemented child stores `~count`, subtracts the increment, and resets to all ones; it has a different R_child but the same executable specification. A parent proof written against child guarantees and projections can remain unchanged. Its freshly checked certificate still names the new actual child/model/source identity.

The checker, not a companion author, owns the final seal tying proof, relation, actual machine, selected spec, ABI, and capture. Ordinary Lean proves bridges; definitional equality is allowed but not mandatory. Original proof/spec source bytes, filenames, module identities, and dependencies remain authoritative; generated namespaces/projections are hygienic, and original modules are not silently rewritten into different source identities. Separate child checking environments may supply generated `Actual` modules, but their results enter a parent only through exact seals checked against its current projections.

Certificates record SHA-256 digests of original source closure, lock, attachments, static arguments, actual normalized graph/state ownership/wiring, foreign artifacts and models, generated Lean, all compiled proof dependencies, semantic options, tool executables/libraries, theorem names/types, schema, and transitive axiom audit. Cache acceptance requires equality of these identities and artifact validation; old reports alone are not proof. Failure invalidates the current attempted result. The base policy permits Lean's standard `propext`, `Quot.sound`, and `Classical.choice`, rejects `sorryAx`, user axioms, and native decision axioms; any alternative policy is a separately named evidence mode with its extra trust listed. No “verified” label may hide a foreign axiom.

This proves the emitted model under its declared assumptions and trusted frontend/emitter/kernel. It does not prove source-to-model correctness, RTL equivalence, synthesis correctness, physical reset, CDC safety, timing, or liveness. Executing the independent Lean model on shared traces is separate finite evidence. Lean `extern`/`implemented_by` replacements, unsafe runtime code, and native dependencies must be separately audited before claiming that the executed reference implements the checked specification.

## 8. Foreign boundaries and event contracts

`extern module` declares a synthesizable foreign component with the same static constructor/domain/typed-port interface as module, resolved by a locked artifact key rather than a native function symbol. Its manifest supplies exact typed ports and static parameters, domain/clock/reset mapping, combinational dependency arcs, sequential timing, target implementation files, executable digital model, and any checked model-to-contract evidence. Every output's combinational input arcs must be declared, including bypasses on otherwise stateful components; absent precision the checker conservatively connects every input leaf to every output. Sequential labels never remove a possible combinational path. Its body permits only static interface computation/declarations, never hardware bindings/resources/instances or diagnostics; the locked model supplies output equations. Instantiation uses the same named instance declaration. A target without the implementation must reject RTL emission, never substitute host execution.

A foreign model assigns each state component to a declared mapped domain. Observation is pure; state holds without its owning edge and selected transitions read the same old global state/inputs. Reset effects occur only at selected edges; resetless state may explicitly ignore reset. Its declared simulation start promises no physical initialization. Use start/relation-based evidence unless the contract independently proves §7 reset establishment. Asynchronous state changes, extra synthesized events and output-as-clock domain creation are not conforming v0.1 behavior. Combinational reset masking is permitted with declared dependency arcs, but cannot certify asynchronous state reset. Packages requiring deferred integration reject as unsupported rather than receiving a synchronous substitute.

```silicon
extern module Multiply8() domains() = "vendor::multiply8" {
    input a: UInt[8];
    input b: UInt[8];
    output product: UInt[16];
}
```

An unproved foreign implementation may be simulated with its model and synthesized under an explicit external trust boundary, but cannot supply a checked implementation guarantee. A checked proof of the digital model alone certifies that model; a physical/RTL implementation correspondence requires separate evidence. Its digest and evidence scope are part of any enclosing result.

Multidomain circuits compose explicit event sets and named complete domain mappings. Ordinary crossing is rejected. Reviewed CDC library APIs instantiate a qualified foreign implementation whose manifest names its specific asynchronous sampling input/stage, source/destination domains, reset behavior, digital model, target stages/placement/retiming protections and physical constraints. Only that implementation boundary permits the declared crossing; no general unsafe cast or domain-retag primitive exists. Later destination flops provide settling time, not mathematical certainty. One-bit level synchronization does not preserve arbitrary pulses or atomic buses. MTBF, skew, reset coordination and physical model correspondence remain explicit external trust/evidence, never consequences of a two-state theorem. See the precise optional level API in the stdlib.

Host C/Rust/C++ interoperability calls the generated model ABI specified in the standard library document, not Silicon modules/helpers directly. It uses opaque instance ownership, canonical arbitrary-width byte records, schema/model identity negotiation, pure evaluation and atomic event stepping. No host pointer, allocation, callback, exception, or IO appears in synthesized hardware. Elaboration-time native FFI is deliberately excluded; deterministic generated source packages supply its useful data boundary without another trusted evaluator.

Cycle contracts require exact timing and full observations. ISA retirement, TileLink-like accepted requests/responses, and latency-changing pipelines use a separately selected executable event adapter: it maps pre-edge outputs and inputs/events to accepted events, including reset cancellation. The adapter must specify invalid payload treatment, ordering, state, reset, and which events count. A stream/transaction refinement then proves event correspondence and any explicit progress assumptions; it is not a weakened cycle certificate. Complete raw output equality remains the cycle rule. The reusable event attachment profile in the library example binds the exact independent spec/observer applications and a local event-simulation theorem, with separate optional task-progress evidence. Existing conforms/using syntax selects it; cycle certificates retain their own theorem type and evidence label.

## 9. Required diagnostics and boundaries

Errors must include source span, specialization/instance path, violated stage/type/domain/resource rule, and the relevant actual versus expected values. Graph errors identify driver paths or a concrete cycle; binding failures identify changed source/model/schema/parameter or missing obligation. A timeout is unknown/failed evidence, not a theorem. Cost reports record target, mapping options, tool identities, configuration, and sampling method; generic cell/LUT counts are not physical PPA.

`diagnostic(message, value)` returns Unit and appends an observation record during elaboration. Message is static String; value may be any typed builder value. Static leaves are rendered as values; reference/resource leaves only as type/domain/owner/origin metadata, never sampled bits. Records contain source span, instance path and ordered call frames. Emission is allowed in pure-static function execution; declaration/type evaluation and hardware-conditioned execution forbid it. It supplies no input, allocation, assumption or graph query result.

Records follow evaluation order and snapshot copied metadata at the call. Display suppression does not skip argument evaluation, errors or evaluator budget charges; each call has the same fixed charge regardless of display. Rendering occurs outside the evaluator; display limits truncate with a deterministic notice without changing elaboration success. Memoization/cache hits must replay the same ordered records, including occurrence-specific call context. Tool options may display call stacks and dump the final validated graph in canonical owner/allocation order, with types, domains, drivers, dependencies and source spans. There is no source API to read that dump. These observation options do not change the graph; original-source edits, including logging edits, still change source-bound certificate identity.

Typed forward/reverse library connections and a complete negotiated generator are specified in the standard library and the example. They use explicit graph bindings and bounded public-schema reflection, without implicit directions or private graph inspection.

Required negative cases are: query factory/effect execution; malformed/duplicate generated fields/keys; computed selection bypassing target/private/pending-root rules; ordinary fn instantiation/module return; child-output or own-input binding; hidden resource constructor arguments; missing/duplicate port bindings including empty ports; dynamic/missing family keys and aggregate partial binding; signal-dependent graph size or branch; host IO/allocation in hardware; zero or mixed integer widths; implicit signedness change; Bool integer condition confusion; cross-domain arithmetic/update; dynamic collection index; nonfitting reset; duplicate/missing state, memory port, or wire driver; escaped instance resource; combinational loop; malformed/OOB static selection; unknown foreign implementation; altered proof capture/ABI/contract/static arguments; runtime assumptions replaced with assertions; proof omitting outputs or unconditional reset; and treating transaction comparison as cycle equality. Runtime RAM OOB is total zero/no-write behavior, not a compile error; a library may expose a fault flag. These choices leave no implicit priority, latch, or undefined memory collision to infer.
