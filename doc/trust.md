# Trust boundary

This document is the authority for the trust boundary. It gives the status, the oracle, the gap, and the issue of each part. [The core IR spec](design/2026-10-08-core-ir.md) defines the parts.

## Statuses

- **Proven**: the Lean kernel checks a proof for all inputs.
- **Validated**: a mechanical oracle checks each run or each input of the corpus. No proof covers the part.
- **Trusted**: no check covers the part. The project assumes that it is correct.
- **Planned: X**: the part gets status X when its issue closes. Until then, no check covers the part.
- **Not supported**: the checker rejects the construct, or the text format has no syntax for it.
- **Out of scope**: Silicon does not check the property. Existing dedicated tools cover it. See [ADR 0005](adr/0005-synchronous-two-state-semantics.md).

## Gaps

### No proof of the Rust checker and interpreter

The Rust binary and the Lean binary each run the shared files of `tests/core/check` and `tests/core/run` against the same expectations. These files find a disagreement only on the designs and the inputs that they hold. The differential tests (`just diff`) widen the inputs to random designs, but they do not give a proof. Issue #10 proves the Rust code against the Lean spec, for example through Aeneas.

### The Rust front end

[The front-end spec](design/2026-10-09-frontend.md) defines the source meaning through the Lean reference elaborator. `silicon-check validate` checks each validated build. A build with `--no-validate` has no check. No proof covers the Rust front end. A proof through Aeneas is the end goal, as issue #10 plans for the core IR. The Lean reference elaborator itself is the spec. Only the human gate checks that it states the intent of the language design.

### The `Mlir` semantics and CIRCT

`lower_correct` proves the Lean lowering against the `Mlir` semantics in Lean. The `Mlir` semantics must match the meaning that CIRCT gives to the same operations. No proof covers this match. `arcilator` runs the same MLIR in the differential tests, and `circt-lec` reads it in LEC. These two oracles check the match.

### The compiled `silicon-check`

Lake compiles `silicon-check` to native code. The Lean kernel does not check the compiled code. The checker thus trusts the Lean compiler, as `native_decide` does.

### A register whose next value is the register itself

The pass `--externalize-registers` of CIRCT 1.160 crashes on a register whose next value is the register itself. A design with `(next r r)` has such a register. A memory model without a write port also has one. LEC skips such designs and prints `SKIP` with #20, so no oracle checks them. Issue #20 tracks a fix.

### A name that is a SystemVerilog keyword

The core IR allows a name such as `logic` or `end`. `firtool` renames such a name in the Verilog, for example to `logic_0`. The LEC wrappers connect the ports by name. Thus LEC reports a failure for such a design, and the design is correct. This gap gives a false failure, never a false pass. Issue #21 tracks a fix.

### Emitted module names

[ADR 0007](adr/0007-mandatory-uniquification.md) requires each emitted module name to hold the package identity. It also requires a name map. `crates/backend-circt/src/lower.rs` does not do this yet. It emits the module name of the core IR unchanged. Two package versions with the same module name thus collide in the output. Slice 5 of the front end adds packages and closes this gap. The front-end spec, section 7.1, gives the plan. Issue #53 tracks it.

### Black boxes

A black box has an assumed contract and no Silicon body. No check covers the contract. The interpreters reject a design with an extern. LEC replaces each black box with the same stand-in on both sides. The stand-in makes each output of the black box an input of the comparison. LEC thus checks the connections of a black box, not its contract. The stand-in needs a clock port, so LEC rejects a design with a black box without a clock port. Issue #37 tracks a fix.

### Asynchronous reset, more than one clock domain, and CDC

The semantics has one clock and synchronous reset only. The parser rejects a reset kind other than `sync` with `E001`. The checker rejects a second clock with `E009`. Issue #11 adds asynchronous reset, more than one clock domain, and CDC primitives.

### Synchronous memory read ports and write masks

A memory of the core IR has a combinational read and no write mask. Real SRAM macros nearly always have a synchronous read, so macro replacement needs these features. Issue #12 adds them.
